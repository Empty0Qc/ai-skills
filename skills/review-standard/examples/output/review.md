## BLOCK（必须修改）

### [src/api/user.go:18] SQL 注入漏洞
**问题：** `userID` 直接从 query string 拼接进 SQL，攻击者可传入 `1 OR 1=1` 等 payload 篡改任意用户数据。
**影响：** 可导致全表数据被篡改，属于高危安全漏洞。
**建议：**
```diff
- db.Exec("UPDATE users SET avatar_url = '" + url + "' WHERE id = " + userID)
+ db.Exec("UPDATE users SET avatar_url = ? WHERE id = ?", url, userID)
```

### [src/api/user.go:8] 未校验 userID 来源，缺少鉴权
**问题：** `userID` 直接取自 query string，任何人可以传入其他用户的 ID 修改其头像。应从认证 token 中提取当前用户 ID。
**影响：** 越权漏洞，任何登录用户可覆盖其他用户的头像。
**建议：** 从请求上下文中取已认证的 `userID`：
```diff
- userID := r.URL.Query().Get("user_id")
+ userID := middleware.GetUserID(r.Context()) // 从 JWT/session 中取
```

### [src/api/user.go:12] 忽略了 io.ReadAll 的错误返回
**问题：** `data, _ := io.ReadAll(file)` 忽略了错误，若读取失败会以空数据继续执行，存储一个空文件。
**建议：**
```diff
- data, _ := io.ReadAll(file)
+ data, err := io.ReadAll(file)
+ if err != nil {
+     http.Error(w, "failed to read file", 400)
+     return
+ }
```

**问题：** 没有对上传文件大小做限制，恶意用户可上传超大文件耗尽内存或存储。
**建议：** 在读取前加大小限制：
```go
r.Body = http.MaxBytesReader(w, r.Body, 5<<20) // 5MB limit
```

**建议：** 使用 `http.DetectContentType(data)` 校验 MIME 类型。
